# 생태계 동적 평형 시뮬레이션 개발 인수인계 문서

**대상 파일:** `ecosystem.html`  
**구현 형태:** HTML·CSS·JavaScript를 모두 포함한 단일 HTML 파일  
**외부 의존성:** 없음  
**문서 기준:** 현재 대화에서 마지막으로 작성한 통합 HTML 코드

---

## 1. 프로젝트 개요

이 프로젝트는 세 개체군으로 구성된 먹이사슬을 시각화하고, 사용자가 개체수를 직접 조절하면서 생태계의 변화를 관찰하는 교육용 시뮬레이션이다.

먹이사슬은 다음과 같다.

> 풀 — 생산자 → 토끼 — 1차 소비자 → 여우 — 2차 소비자

주요 목적은 다음과 같다.

1. 생산자와 소비자가 서로 영향을 주고받는 현상을 관찰한다.
2. 특정 개체군을 늘리거나 줄였을 때 다른 개체군이 어떻게 반응하는지 확인한다.
3. 개체수가 고정된 숫자로 유지되는 것이 아니라 환경에 따라 변동하는 동적 평형을 표현한다.
4. 개체수 변화 속도가 다른 두 수식을 선택하여 비교한다.
5. 개체수 그래프, 개체별 도형, 개체수 피라미드로 같은 상태를 다양한 방식으로 보여준다.

실제 생태계를 정밀하게 예측하는 연구용 모델이 아니라, 상호작용과 변화 양상을 설명하기 위한 **교육용 연속 개체수 모델**이다.

---

## 2. 지금까지의 요구사항과 구현 방향

### 2.1 초기 통합 요구사항

기존 시뮬레이션을 하나의 HTML 파일로 정리하는 것이 첫 번째 요구사항이었다.

통합 과정에서 유지한 기능은 다음과 같다.

- HTML 파일 하나만으로 실행
- 한국어·영어 UI
- 생산자·1차 소비자·2차 소비자 시각화
- 개체수 추가 및 감소
- 그래프에 개체수 조절 시각과 변경량 표시
- 변경 전·후 개체수 상세 표시
- 변경 기록 유지
- 개체수 피라미드
- 피라미드의 테두리형 비교 화살표
- 실행·일시정지·배속
- 시작 조건 선택과 초기화
- 하단 `i` 버튼을 통한 안내 표시

### 2.2 수식 확장 요구사항

사용자는 기존 수식의 작동 방식은 만족했지만, 특정 개체군이 크게 증가했을 때 자연적인 반응이 너무 빠르게 나타나는 점을 완화하고자 했다.

대표적인 요청은 다음과 같다.

> 생산자가 크게 증가했을 때 개체수가 갑자기 500대 수준으로 감소하는 것처럼 보이지 않도록, 기존 수식을 기반으로 반응이 느린 버전을 추가한다.

이를 위해 다음 원칙으로 구현했다.

1. 기존 수식을 변경하거나 삭제하지 않는다.
2. 기존 수식의 이름을 **수식v1**로 정한다.
3. 기존 수식의 변화율을 완화하는 새 수식을 **수식v2**로 추가한다.
4. 두 수식을 사용자가 선택할 수 있게 한다.
5. 선택 UI는 `i` 버튼 안내 화면 맨 아래에 배치한다.
6. 설정 버튼 아래에 두 수식의 설명을 추가한다.
7. 수식을 바꾸더라도 시간·개체수·기록은 초기화하지 않는다.

### 2.3 중요한 구현 해석

현재 수식v2는 다음 방식이다.

> 기존 수식으로 계산한 순간 변화율을 부드럽게 줄인다.

다음 방식은 아니다.

- 단순한 화면 애니메이션 지연
- 실행 배속 감소
- 과거 개체수를 참조하는 시간 지연 모델
- 별도의 적응 상태를 가진 관성 모델
- 개체수 변경 버튼의 효과를 서서히 적용하는 모델

이 차이는 후속 개발에서 중요하다.

# 3. 실행 방법과 배포 형태

## 3.1 실행

1. 전체 코드를 `ecosystem.html`로 저장한다.
2. 브라우저에서 연다.
3. `시작 / Start` 버튼을 누른다.

외부 서버나 패키지 설치는 필요하지 않다.

## 3.2 사용 기술

| 구분 | 기술 |
|---|---|
| 문서 및 UI | HTML |
| 스타일 | CSS |
| 상태와 수치 계산 | 순수 JavaScript |
| 생태계 시각화 | Canvas 2D |
| 개체수 그래프 | Canvas 2D |
| 개체수 피라미드 | SVG |
| 실행 루프 | `requestAnimationFrame()` |
| 숫자 서식 | `toLocaleString("ko-KR")` |

## 3.3 데이터 저장 범위

모든 데이터는 브라우저 메모리에만 저장된다.

저장되지 않는 항목:

- 현재 개체수
- 경과 시간
- 그래프 기록
- 개체수 변경 기록
- 선택한 수식
- 배속
- 기타 UI 설정

따라서 페이지를 새로고침하거나 닫으면 초기 상태로 돌아간다.

`localStorage`, 서버 저장, 파일 내보내기는 구현되어 있지 않다.

# 5. 코드 구성

현재 코드는 단일 `<script>` 안에 있으며, 주요 영역은 다음과 같다.

```text
상수와 상태
    ↓
환경 계산
    ↓
수식v1 / 수식v2
    ↓
수치 적분
    ↓
개체 위치와 이동
    ↓
개체수 조절과 기록
    ↓
실행 / 초기화
    ↓
Canvas 공통 처리
    ↓
생태계 렌더링
    ↓
그래프 렌더링
    ↓
툴팁
    ↓
과거 개체수 조회
    ↓
피라미드와 화살표
    ↓
요약 및 수식 UI
    ↓
이벤트 연결
    ↓
메인 프레임 루프
```

DOM 조회에는 다음 보조 함수를 사용한다.

```javascript
const $ = id => document.getElementById(id);
```

외부 모듈이나 클래스 구조는 사용하지 않는다.

# 6. 주요 상수와 상태

## 6.1 개체군 인덱스

배열의 인덱스는 전체 코드에서 동일하게 사용한다.

```javascript
0: 생산자
1: 1차 소비자
2: 2차 소비자
```

예:

```javascript
state = [650, 80, 15];
```

의미:

```text
생산자 650
1차 소비자 80
2차 소비자 15
```

| 변수 | 의미 |
|---|---|
| `state` | 현재 개체수 계산값 배열 |
| `time` | 경과한 가상 시간 |
| `running` | 실행 여부 |
| `accumulator` | 아직 적분하지 않은 누적 가상 시간 |
| `lastTimestamp` | 이전 애니메이션 프레임 시각 |

# 7. 시작 조건

## 7.1 기본 프리셋

```javascript
const PRESETS = {
  balanced: [650, 80, 15],
  equilibrium: [500, 100, 20],
  herbivoreHigh: [650, 240, 15],
  predatorHigh: [650, 100, 80],
  noPredator: [650, 80, 0]
};
```

| 프리셋 | 생산자 | 1차 소비자 | 2차 소비자 |
|---|---:|---:|---:|
| 기본 관찰 | 650 | 80 | 15 |
| 기준 평형 | 500 | 100 | 20 |
| 1차 소비자 과다 | 650 | 240 | 15 |
| 2차 소비자 과다 | 650 | 100 | 80 |
| 2차 소비자 없음 | 650 | 80 | 0 |

## 7.2 입력 규칙

초기 개체수는 다음 범위여야 한다.

```text
0 이상 3,000 이하
```

소수 입력이 가능하다.

입력창을 직접 수정하면 프리셋 표시가 `직접 입력 / Custom`으로 바뀐다.

주의:

> 프리셋을 선택하는 것만으로 현재 실행 상태가 바뀌지는 않는다.

프리셋 선택은 입력창 값만 바꾸며, 실제 적용은 `조건 적용·초기화` 버튼을 눌렀을 때 이루어진다.

# 8. 생태계 모델: 수식v1

## 8.1 변수 정의

| 기호 | 의미 |
|---|---|
| \(P\) | 생산자 개체수 |
| \(H\) | 1차 소비자 개체수 |
| \(C\) | 2차 소비자 개체수 |
| \(t\) | 가상 시간 |

## 8.2 파라미터

```javascript
const PARAM = {
  r: 0.8,
  K: 1000,
  a: 0.004,
  b: 0.01,
  eH: 0.2,
  eC: 0.2,
  dH: 0.1,
  dC: 0.1,
  sH: 0.001,
  sC: 0.005
};
```

| 파라미터 | 의미 |
|---|---|
| \(r\) | 생산자 기본 성장률 |
| \(K\) | 생산자 기본 환경수용력 |
| \(a\) | 생산자와 1차 소비자의 섭식 상호작용 계수 |
| \(b\) | 1차 소비자와 2차 소비자의 포식 상호작용 계수 |
| \(e_H\) | 생산자 섭식량의 1차 소비자 증가 전환 계수 |
| \(e_C\) | 포식량의 2차 소비자 증가 전환 계수 |
| \(d_H\) | 1차 소비자 기본 사망률 |
| \(d_C\) | 2차 소비자 기본 사망률 |
| \(s_H\) | 1차 소비자 밀도 의존 감소 계수 |
| \(s_C\) | 2차 소비자 밀도 의존 감소 계수 |

환경에 따라 실제 적용되는 성장률·수용력·사망률은 달라진다.

## 8.3 방정식

### 생산자

\[
\frac{dP}{dt}
=
r_{\mathrm{env}}P
\left(1-\frac{P}{K_{\mathrm{env}}}\right)
-aPH
\]

구성:

1. 로지스틱 성장
2. 1차 소비자에 의한 섭식 감소

### 1차 소비자

\[
\frac{dH}{dt}
=
e_HaPH-bHC-d_{H,\mathrm{env}}H-s_HH^2
\]

구성:

1. 생산자 섭식에 따른 증가
2. 2차 소비자 포식에 따른 감소
3. 기본 사망
4. 밀도가 높아졌을 때 추가 감소

### 2차 소비자

\[
\frac{dC}{dt}
=
e_CbHC-d_{C,\mathrm{env}}C-s_CC^2
\]

구성:

1. 1차 소비자 포식에 따른 증가
2. 기본 사망
3. 밀도가 높아졌을 때 추가 감소

## 8.4 코드

```javascript
function derivativeV1([P, H, C]) {
  const p = PARAM;
  const env = getConditions();

  const herbivory = p.a * P * H;
  const predation = p.b * H * C;

  return [
    env.growth * P * (1 - P / env.capacity) - herbivory,

    p.eH * herbivory - predation -
      env.mortalityH * H - p.sH * H * H,

    p.eC * predation -
      env.mortalityC * C - p.sC * C * C
  ];
}
```

## 8.5 기준 평형

환경 변동이 없고 기본 파라미터를 사용할 때 다음 상태에서 세 변화율이 모두 0이다.

```javascript
[500, 100, 20]
```

확인:

### 생산자

\[
0.8 \times 500 \times (1-500/1000)
-
0.004 \times 500 \times 100
=200-200=0
\]

### 1차 소비자

\[
40-20-10-10=0
\]

### 2차 소비자

\[
4-2-2=0
\]

다만 실제 실행에서는 환경이 지속해서 변하므로, 기준 평형에서 시작하더라도 그대로 정지해 있지는 않는다.

또한 이 상태는 기준으로 사용하는 양의 평형점이며, 모델에 존재하는 모든 평형 상태가 이것 하나라는 뜻은 아니다.

## 8.6 기존 수식의 빠른 반응 원인

생산자의 자연 감소 항에는 다음 형태가 포함된다.

\[
-\frac{r_{\mathrm{env}}}{K_{\mathrm{env}}}P^2
\]

따라서 생산자 수가 커지면 감소 항도 제곱에 비례하여 커질 수 있다.

예를 들어 환경이 기준 상태이고 다음과 같다면:

```text
P = 1100
H = 100
C = 20
```

생산자 변화율은 다음과 같다.

\[
0.8 \times 1100 \times (1-1.1)
-
0.004 \times 1100 \times 100
\]

\[
=-88-440=-528
\]

이는 가상 시간당 순간 변화율이다.

따라서 개체수를 크게 추가한 직후 빠르게 감소하는 모습이 나타날 수 있다. 수식v2는 이 변화율을 완화하기 위해 추가되었다.

# 9. 생태계 모델: 수식v2

## 9.1 설계 목적

수식v1의 생태적 상호작용 구조를 그대로 사용하면서, 급격한 증가·감소를 줄이는 것이 목적이다.

핵심 조건:

- 수식v1 유지
- 같은 상태에서 증가·감소 방향 유지
- 변화율이 0인 상태 유지
- 작은 변화도 기존보다 느리게 반영
- 큰 변화는 더 강하게 완화
- 직접 조절 버튼은 즉시 반영

## 9.2 방정식

개체군별 수식v1의 변화율을 \(F_1\), 현재 개체수를 \(N\)이라고 할 때:

\[
F_2
=
\frac{F_1}
{2+\frac{|F_1|}{0.12\max(N,1)}}
\]

현재 개체수가 정확히 0이면 해당 개체군의 변화율은 0으로 반환한다.

## 9.3 파라미터

```javascript
const FORMULA_V2 = {
  responseDivisor: 2,
  maxRelativeRate: 0.12
};
```

### `responseDivisor`

작은 변화율에 적용되는 기본 완화 정도다.

현재 값은 2이므로 \(F_1\)이 충분히 작을 때:

\[
F_2 \approx \frac{F_1}{2}
\]

즉, 같은 상태에서 기존의 약 절반 속도로 반응한다.

### `maxRelativeRate`

큰 변화율에 대한 순간 변화율 제한 수준이다.

현재 값은 0.12다.

\[
|F_2| < 0.12\max(N,1)
\]

따라서 \(N \geq 1\)이면:

\[
\left|\frac{F_2}{N}\right| < 0.12
\]

가상 시간당 순간 상대 변화율의 크기를 12% 미만으로 제한한다.

주의:

> 가상 시간 1이 지났을 때 총개체수 변화가 반드시 12% 이하라는 뜻은 아니다.

연속적으로 변하는 순간 변화율의 상한이다. 예를 들어 증가율이 상대 상한에 가까운 상태로 계속 유지된다면, 한 시간 구간의 누적 증가 비율은 복리 효과로 12%를 넘을 수 있다.

## 9.4 코드

```javascript
function derivativeV2(values) {
  const originalRates = derivativeV1(values);

  return originalRates.map((rate, index) => {
    const population = Math.max(0, values[index]);

    if (population === 0) return 0;

    const rateLimit =
      FORMULA_V2.maxRelativeRate * Math.max(population, 1);

    const damping =
      FORMULA_V2.responseDivisor +
      Math.abs(rate) / rateLimit;

    return rate / damping;
  });
}
```

## 9.5 계산 예시

앞의 예시를 그대로 사용한다.

```text
현재 생산자 = 1100
수식v1 생산자 변화율 = -528
```

수식v2의 제한 기준은:

\[
L=0.12 \times 1100=132
\]

따라서:

\[
F_2
=
\frac{-528}{2+528/132}
=
\frac{-528}{6}
=-88
\]

| 항목 | 순간 생산자 변화율 |
|---|---:|
| 수식v1 | -528 |
| 수식v2 | -88 |

동일한 상태에서 감소 속도가 크게 완화된다.

실행 중에는 개체수와 환경이 계속 바뀌므로 이 값이 계속 유지되는 것은 아니다.

## 9.6 유지되는 성질

같은 개체수와 환경 상태에서 분모는 양수이므로:

- \(F_1 > 0\)이면 \(F_2 > 0\)
- \(F_1 < 0\)이면 \(F_2 < 0\)
- \(F_1 = 0\)이면 \(F_2 = 0\)

따라서 같은 환경에서 평형 조건은 유지된다.

## 9.7 유지되지 않는 성질과 해석상 주의

수식v2는 각 개체군의 최종 변화율을 서로 다른 비율로 완화한다.

따라서 수식v1과 비교했을 때:

- 시간에 따른 궤적이 달라질 수 있다.
- 생산자와 소비자가 서로 반응하는 상대 속도가 달라질 수 있다.
- 진동의 크기와 위상이 달라질 수 있다.
- 환경이 변할 때 결과가 달라질 수 있다.

특히 동일한 섭식·포식 항을 사용하더라도, 최종 변화율을 개체군별로 완화하므로 **먹이 감소량과 소비자 증가량의 결합 비율이 v1과 동일하게 유지되는 구조는 아니다.**

현재 모델은 개체수 기반 교육용 모델이며, 엄밀한 물질·에너지 보존 모델로 설명하면 안 된다.

## 9.8 튜닝 방향

| 원하는 결과 | 조정 방향 |
|---|---|
| 전반적으로 더 느리게 | `responseDivisor` 증가 |
| 전반적으로 덜 느리게 | `responseDivisor` 감소 |
| 급격한 변화를 더 강하게 억제 | `maxRelativeRate` 감소 |
| 큰 변화를 더 허용 | `maxRelativeRate` 증가 |

후속 개발 시에는 값을 바꾼 후 프리셋과 대량 추가 시나리오를 모두 검증해야 한다.

# 10. 수식 선택과 적용 범위

## 10.1 선택 함수

```javascript
function derivative(values) {
  return formulaVersion === "v2"
    ? derivativeV2(values)
    : derivativeV1(values);
}
```

모든 수치 적분은 이 함수를 통해 계산한다.

## 10.2 적용되는 곳

선택한 수식은 다음 항목에 반영된다.

- 실제 개체수 변화
- 이후 그래프
- 이후 피라미드 너비
- 하단 개체수 변화 방향

## 10.3 바뀌지 않는 곳

수식을 바꿔도 다음은 유지된다.

- 현재 개체수
- 현재 시간
- 실행·일시정지 여부
- 기존 그래프 기록
- 기존 개체수 변경 기록
- 개체별 위치
- 현재 환경 상태
- 배속

## 10.4 기본값과 초기화

최초 페이지 로드 시:

```javascript
formulaVersion = "v1";
```

`조건 적용·초기화`를 눌러도 선택한 수식은 유지된다.

페이지를 새로고침하면 다시 수식v1이 기본값이 된다.

## 10.5 현재 기록상의 제한

수식 전환 시 현재 상태를 `history`에 기록하지만 다음 정보는 별도로 저장하지 않는다.

- 수식 전환 이벤트 목록
- 수식 전환 시각의 그래프 마커
- 각 그래프 구간에서 사용한 수식 버전

따라서 실행 중 여러 번 수식을 전환하면 그래프에는 여러 수식의 결과가 이어지지만, 그래프만 보고 전환 지점을 알 수는 없다.

# 11. 환경 변화 모델

## 11.1 상태

```javascript
environment = {
  weather: 0,
  resource: 0
};
```

- `weather`: 성장과 사망률에 영향을 주는 환경 상태
- `resource`: 환경수용력에 영향을 주는 자원 상태

## 11.2 확률 과정

각 환경 변수는 다음 형태로 갱신한다.

\[
x_{t+\Delta t}
=
x_t e^{-\Delta t/\tau}
+
\sigma\sqrt{1-e^{-2\Delta t/\tau}}Z
\]

여기서:

- \(\tau\): 시간 상관 척도
- \(\sigma\): 장기 변동 규모
- \(Z\): 표준정규 난수

코드는 평균 0으로 되돌아가는 상관된 확률 변동을 만든다.

```javascript
environment.weather = advance(environment.weather, 9, 0.8);
environment.resource = advance(environment.resource, 22, 0.7);
```

## 11.3 실제 파라미터로 변환

먼저:

```javascript
const weather = Math.tanh(environment.weather);
const resource = Math.tanh(environment.resource);
```

이를 이용해:

```javascript
growth = r * (1 + 0.28 * weather);
capacity = K * (1 + 0.25 * resource);
mortalityH = dH * (1 - 0.18 * weather);
mortalityC = dC * (1 - 0.12 * weather);
```

대략적인 변동 범위:

| 항목 | 기본값 대비 범위 |
|---|---|
| 생산자 성장률 | 72%~128% 사이 |
| 환경수용력 | 75%~125% 사이 |
| 1차 소비자 사망률 | 82%~118% 사이 |
| 2차 소비자 사망률 | 88%~112% 사이 |

`tanh()`는 유한한 입력에서 정확히 ±1에 도달하지 않으므로 엄밀하게는 양 끝값에 접근하는 범위다.

## 11.4 수식v2에서도 환경은 느려지지 않음

수식v2는 개체수 변화율만 줄인다.

환경 갱신 속도는 수식v1과 같다.

따라서:

> 수식v2는 환경 변화에 비해 개체군이 상대적으로 더 느리게 반응하는 모델이다.

## 11.5 재현성

현재 난수는 `Math.random()`을 사용한다.

따라서:

- 같은 초기값으로 실행해도 결과가 달라질 수 있다.
- v1과 v2를 각각 실행했을 때 동일한 환경 경로를 자동으로 공유하지 않는다.
- 소비자 이동용 난수도 같은 전역 난수원을 사용한다.

정확한 비교 실험이 필요하면 환경용 시드 난수와 시각화용 난수를 분리해야 한다.

# 12. 수치 적분

## 12.1 방식

4차 Runge–Kutta, 즉 RK4를 사용한다.

```javascript
const k1 = derivative(values);
const k2 = derivative(shifted(values, k1, h / 2));
const k3 = derivative(shifted(values, k2, h / 2));
const k4 = derivative(shifted(values, k3, h));
```

최종 상태:

\[
x_{n+1}
=
x_n+
\frac{h}{6}(k_1+2k_2+2k_3+k_4)
\]

## 12.2 음수 처리

적분이 끝난 최종 상태에 다음 처리를 한다.

```javascript
Math.max(0, nextValue)
```

따라서 저장되는 개체수는 음수가 되지 않는다.

다만 RK4 중간 평가 상태까지 항상 비음수로 제한하는 것은 아니다.

극단적인 개체수와 큰 변화율에서는 중간 상태가 비물리적인 값이 될 가능성이 있으므로, 현재 구현이 모든 입력에서 양수성을 엄밀히 보장하는 적분기라고 설명해서는 안 된다.

## 12.3 환경과 적분 순서

각 `STEP`마다:

1. 환경 갱신
2. 갱신된 환경으로 RK4 계산
3. 개체수 저장
4. 시간 증가

한 RK4 단계 안의 네 번의 변화율 평가에서는 같은 환경 상태를 사용한다.

환경은 확률적으로 별도 갱신되므로, 전체 시스템을 단순히 “확률계까지 포함한 4차 정확도”라고 표현하면 안 된다.

## 12.4 비정상 값 처리

계산 결과에 `NaN` 또는 `Infinity`가 있으면:

- 실행 중지
- 누적 시간 초기화
- 오류 메시지 표시

```text
수치 계산 오류입니다. 시작 조건을 초기화하세요.
```

이는 오류 감지이며, 극단적인 입력에서도 계산이 항상 안정적이라는 보장은 아니다.

# 13. 실제 시간과 가상 시간

메인 루프에서 다음과 같이 누적한다.

```javascript
accumulator += elapsed * 2 * Number($("speed").value);
```

정상적인 프레임 진행 기준:

| 배속 | 실제 1초당 가상 시간 |
|---|---:|
| 0.5× | 약 1 |
| 1× | 약 2 |
| 2× | 약 4 |
| 4× | 약 8 |
| 8× | 약 16 |

중요:

> UI의 1×는 “실제 1초 = 가상 시간 1”이 아니라 기본 실행 속도다.

## 13.1 프레임 시간 제한

```javascript
Math.min((timestamp - lastTimestamp) / 1000, 0.1)
```

한 프레임에 반영하는 실제 시간은 최대 0.1초로 제한한다.

장점:

- 탭 복귀 후 과도한 계산 방지
- 긴 지연 이후 급격한 시간 진행 방지

결과:

- 프레임 지연이 크면 실제 경과 시간 전체를 따라잡지 않는다.
- 낮은 프레임률에서는 실제 시간 대비 시뮬레이션 진행이 느려질 수 있다.

## 13.2 탭 전환

`visibilitychange`에서 `lastTimestamp`를 초기화한다.

탭을 오래 비웠다가 돌아와도 그 전체 시간을 한 번에 계산하지 않도록 한다.

# 14. 개체수 직접 조절

## 14.1 입력 조건

추가·감소 수량은 다음 조건을 만족해야 한다.

```text
1~3000 사이의 정수
```

초기 개체수와 달리 소수 조절은 허용하지 않는다.

## 14.2 추가

```javascript
after = before + amount;
```

## 14.3 감소

```javascript
after = Math.max(0, before - amount);
```

요청한 감소량이 현재 개체수보다 크면 실제로는 0까지만 감소한다.

예:

```text
현재 7.5개체
10개체 감소 요청
결과 0개체
기록된 실제 변경량 -7.5
```

## 14.4 실행 상태 유지

직접 조절은 다음을 바꾸지 않는다.

- 시간
- 실행 여부
- 수식
- 환경
- 기존 기록

## 14.5 수식v2와의 관계

추가·감소 버튼은 수식v2에서도 즉시 적용된다.

예:

```text
생산자 500
+600 버튼 조작
즉시 1100
이후 자연적인 변화만 수식v2로 완화
```

# 15. 기록 데이터 구조

## 15.1 그래프 기록

```javascript
{
  t: 12.4,

}
```

일반적으로 가상 시간 0.2마다 기록한다.

추가 기록 시점:

- 초기화 직후
- 직접 조절 직전
- 직접 조절 직후
- 수식 전환 시점

## 15.2 개체수 변경 이벤트

```javascript
{
  id: 1,
  t: 12.4,
  species: 0,
  before: 620.3,
  after: 1220.3,
  delta: 600
}
```

## 15.3 같은 시각의 변경 전·후 기록

직접 개체수를 조절할 때:

```javascript
recordState();
state[species] = after;
recordState();
```

이를 통해 그래프에 순간적인 수직 변화가 나타난다.

## 15.4 보관 정책

### `history`

최근 120시간 구간을 유지한다.

보간을 위해 구간 직전 기록 하나를 추가로 유지할 수 있다.

### `changeEvents`

시간 기준 삭제를 하지 않는다.

초기화 전까지 모든 직접 조절 기록을 유지한다.

### 기록 표

모든 변경 행을 DOM에 유지하며 최신 기록을 위에 추가한다.

장시간 대량 조절 시 메모리와 DOM 크기가 증가할 수 있다.

---

# 16. 개체수 그래프

## 16.1 좌표축

가로축은 가상 시간이다.

```javascript
minT = Math.max(0, time - 120);
maxT = Math.max(30, time);
```

따라서:

- 시작 직후에는 0~30을 표시
- 이후에는 현재 시간까지 표시
- 120시간 이후에는 최근 120시간 표시

## 16.2 세로축 모드

### 실제 개체수

소수점 계산값을 그대로 그린다.

### 기준 대비 백분율

기준값:

```javascript
[500, 100, 20]
```

계산:

\[
\text{상대값}
=
\frac{\text{현재 개체수}}{\text{기준 개체수}}
\times100
\]

세 개체군 모두 기준 상태일 때 100%다.

## 16.3 자동 축척

세로축 최댓값은 기록과 현재 상태를 참고하여 자동으로 정한다.

여유 공간으로 약 12%를 추가한다.

주의할 점:

- 축척은 고정이 아니다.
- 대량 추가 직후 그래프 전체의 높이 비율이 달라질 수 있다.
- 같은 기울기라도 세로축 범위에 따라 시각적으로 다르게 보일 수 있다.

## 16.4 변경 표시

직접 조절한 이벤트마다:

- 세로 점선
- 변경 후 위치의 점
- 이벤트 번호·시각·개체군·변경량 라벨

을 표시한다.

## 16.5 라벨 배치

최대 5개 행에 분산 배치한다.

공간이 부족하면 겹칠 수 있으며, 모든 상황에서 겹침을 완전히 제거하는 알고리즘은 아니다.

그래서 변경 기록 표를 별도로 제공한다.

## 16.6 툴팁

다음 영역에서 표시한다.

- 변경 라벨
- 변경 시점 세로선 근처

포인터 이벤트를 사용하므로 마우스와 터치를 처리한다.

같은 시각에 여러 이벤트가 있으면 최대 5개 상세 내역을 표시하고 나머지는 표를 확인하도록 안내한다.

# 17. 생태계 시각화

## 17.1 도형 수와 실제 계산값

계산값은 연속적인 실수다.

도형 수와 주요 숫자는 반올림한다.

```javascript
Math.max(0, Math.round(value))
```

예:

| 계산값 | 표시 숫자 및 도형 수 |
|---:|---:|
| 10.49 | 10 |
| 10.50 | 11 |
| 0.49 | 0 |

따라서 화면에서 0으로 보여도 계산상으로는 0보다 클 수 있다.

“정확히 0인 종은 자연적으로 재등장하지 않는다”는 규칙과 구분해야 한다.

## 17.2 개체별 시각 상태

```javascript
{
  x,
  y,
  angle,
  speed,
  turnRate
}
```

좌표는 0~1 범위의 정규화 좌표다.

## 17.3 이동

- 생산자는 이동하지 않는다.
- 소비자는 확률적으로 방향을 바꾸며 움직인다.
- 경계에 닿으면 반사한다.
- 2차 소비자가 1차 소비자보다 조금 더 빠르게 움직인다.

## 17.4 생태 계산과의 분리

도형 간 위치 관계는 수식에 영향을 주지 않는다.

구현되지 않은 항목:

- 실제 충돌 판정
- 개체별 먹이 탐색
- 먹이를 먹는 개별 이벤트
- 공간별 자원
- 이동 거리에 따른 에너지 소비

즉, 개체군 모델은 공간이 없는 집합 모델이고, 이동은 설명용 시각 효과다.

# 18. 개체수 피라미드

## 18.1 구조

위에서부터:

1. 2차 소비자
2. 1차 소비자
3. 생산자

각 층 높이는 100px다.

## 18.2 너비

```javascript
width = population * 0.48;
```

모든 개체군이 동일한 축척을 사용한다.

계산값이 0이면 해당 사각형의 너비도 0이다.

## 18.3 의미

이 피라미드는 **개체수 피라미드**다.

다음으로 해석하면 안 된다.

- 생물량 피라미드
- 에너지 피라미드
- 개체 크기 비교
- 총질량 비교

소비자가 매우 많으면 위층이 더 넓어질 수 있다.

## 18.4 가로 스크롤

큰 개체수에서는 SVG 너비를 확장한다.

패널보다 넓어지면 가로 스크롤로 확인한다.

무조건 패널 너비에 맞춰 축소하지 않으므로 동일 축척을 유지할 수 있다.

# 19. 피라미드 과거 비교

## 19.1 기능

현재 상태와 설정한 시간 전 상태를 비교한다.

기본:

```text
5시간 전
```

허용 범위:

```text
0.2~120시간 전
```

## 19.2 과거 상태 조회

`getPopulationAt()`은 다음 방식으로 동작한다.

1. 요청 시간이 기록 범위 안인지 확인
2. 이진 탐색으로 이전 기록 검색
3. 정확히 같은 시각이면 해당 상태 사용
4. 사이 시각이면 선형 보간

## 19.3 동일 시각에 여러 상태가 있는 경우

직접 조절로 같은 시각의 기록이 여러 개 있으면 마지막 변경 후 상태를 사용한다.

## 19.4 화살표

| 상태 | 표시 |
|---|---|
| 증가 | 오른쪽 화살표 |
| 감소 | 왼쪽 화살표 |
| 변화 거의 없음 | 양방향 화살표 |
| 과거 기록 부족 | 대기 |

화살표는 흰색 내부와 색상 테두리를 가진 SVG 경로다.

## 19.5 변화 없음 판정

부동소수점 오차를 고려해 다음 허용 오차를 사용한다.

```javascript
1e-6 * Math.max(
  1,
  Math.abs(previous),
  Math.abs(current)
)
```

## 19.6 비교에 포함되는 변화

피라미드 비교는 원인별 구분 없이 최종 개체수 차이를 비교한다.

따라서 다음이 모두 포함된다.

- 자연 성장
- 섭식·포식
- 사망
- 환경 변화
- 직접 추가·감소
- 중간에 수식을 전환한 효과

# 20. 하단 변화 방향

현재 선택한 수식의 순간 변화율을 사용한다.

```javascript
relativeRate = rate / Math.max(population, 1);
```

판정:

```text
+0.002 초과 → ↑
-0.002 미만 → ↓
그 외       → ↔
```

이 표시는 과거 기록 대비 차이가 아니다.

> 현재 상태에서 앞으로 어느 방향으로 움직이려 하는지를 나타내는 순간 변화율 표시다.

수식v2는 변화율을 줄이므로 수식v1과 같은 방향이더라도 `↔` 범위에 들어갈 수 있다.

- 개체수
- 시간
- 실행 상태
- 누적 시간
- 프레임 기준 시각
- 다음 샘플 시각
- 그래프 기록

- 이벤트 번호
- 그래프 감지 영역
- 포인터 상태
- 환경 상태
- 개체별 위치
- 변경 기록 표

유지하는 항목:

- 선택한 수식

- 피라미드 비교 시간
- 안내 패널의 열림 상태

초기화 후에는 자동 실행하지 않고 일시정지 상태가 된다.

# 24. 반응형·접근성 처리

## 24.1 반응형

```css
@media (max-width: 850px) {
```

## 24.2 고해상도 Canvas

`devicePixelRatio`에 맞춰 Canvas 실제 해상도를 조정한다.

CSS 크기와 실제 픽셀 크기를 구분하여 고해상도 화면에서 흐릿해지는 현상을 줄인다.

구현된 항목:

- 입력 요소의 `label`
- 버튼의 `type="button"`

- 연결 대상의 `aria-controls`
- 오류 영역의 `role="alert"`
- 상태 메시지의 `role="status"`

- SVG 제목과 설명
- 키보드 포커스 표시

- Canvas 내부 그래프의 모든 수치가 스크린리더용 표로 제공되지는 않는다.
- 색상 외에도 도형과 텍스트를 사용하지만 완전한 접근성 검증은 별도로 필요하다.

# 25. 현재 구현의 한계와 기술적 주의사항

## 25.1 실제 개체가 아니라 연속 개체수 모델

실수 개체수를 계산한다.

따라서 0.2개체 같은 내부 값이 존재한다.

정수 기반 개체별 출생·사망 모델이 아니다.

## 25.2 수식v2는 시간 지연 모델이 아님

현재 값만으로 변화율을 계산한다.

과거 개체수나 지연된 먹이량을 수식에 사용하지 않는다.

실제 생태적 지연을 구현하려면 별도의 설계가 필요하다.

## 25.3 총개체수 상한 없음

초기 입력과 한 번의 조절량은 제한하지만 반복 추가로 현재 개체수는 3,000을 넘을 수 있다.

따라서 매우 많은 개체를 추가하면:

- 도형 수 증가
- 이동 계산 증가
- Canvas 처리 증가
- SVG 너비 증가

등으로 성능이 저하될 수 있다.

## 25.4 일시정지 중에도 매 프레임 다시 그림

현재는 `running === false`여도 `render()`를 계속 호출한다.

단순하지만 CPU 사용 측면에서는 비효율적이다.

개선 시:

- 실행 중에는 연속 렌더링
- 일시정지 중에는 상태 변경·리사이즈 시에만 렌더링

하는 구조를 고려할 수 있다.

## 25.5 시각 상태 배열의 크기

자연적인 개체수 감소에서는 `visualSeeds` 배열을 즉시 줄이지 않는다.

이후 다시 증가하면 기존 시각 상태를 재사용한다.

직접 감소 버튼을 사용할 때는 해당 배열을 줄인다.

따라서 과거에 개체수가 매우 컸다면 그에 해당하는 시각 상태가 메모리에 남을 수 있다.

## 25.6 변경 기록 무제한 증가

`changeEvents`와 기록 표는 초기화 전까지 계속 증가한다.

필요하면 다음을 추가할 수 있다.

- 최대 기록 수
- CSV 내보내기
- 오래된 기록 접기
- 표 가상 스크롤

## 25.7 수식 전환의 추적성 부족

수식 전환 이벤트를 별도로 저장하지 않는다.

실험 기록용으로 사용하려면 전환 이력을 추가하는 것이 좋다.

## 25.8 확률 경로 재현 불가

시드 난수가 없으므로 같은 결과를 다시 실행하기 어렵다.

모델 비교와 회귀 테스트에는 별도 개선이 필요하다.

## 25.9 수치 안정성

고정 간격 RK4와 최종 음수 절단을 사용한다.

극단적인 입력에서 다음 문제를 완전히 방지하지는 못한다.

- 중간 상태의 음수
- 수치 발산
- 비현실적인 큰 변화
- 음수 절단에 따른 오차

## 25.10 최근 120시간 표시의 경계 처리

보간용으로 창 이전 기록 하나를 유지하고 이를 선으로 이어 그린다.

또한 세로축 최댓값을 계산할 때 보관 중인 모든 기록을 참고한다.

따라서 화면 밖 직전의 큰 값이 축척에 일시적으로 영향을 줄 수 있다.

## 25.11 직접 변경 마커 위치

마커는 변경 직후 값에 표시된다.

이후 같은 시각에 추가 변경이 있더라도 기존 이벤트의 마커는 각 이벤트의 변경 직후 상태를 유지한다.

이는 의도된 기록 방식이다.

## 26.8 v1·v2 변화율 단위 테스트

환경을 고정한 상태에서 임의의 비음수 상태 배열에 대해 검사한다.

### 방향 유지

```text
sign(F1[i]) === sign(F2[i])
```

0 처리와 부동소수점 오차를 고려한다.

### 크기 완화

현재 설정에서는 일반적으로:

\[
|F_2| \leq \frac{|F_1|}{2}
\]

### 상한

\[
|F_2| < 0.12\max(N,1)
\]

### 기준 평형

환경이 0일 때:

```javascript
derivativeV1([500, 100, 20])
derivativeV2([500, 100, 20])
```

두 결과가 허용 오차 내에서 모두 0인지 확인한다.

## 26.9 급격한 생산자 증가 비교


정확한 비교를 위해 환경을 고정하거나 동일한 환경 경로를 사용해야 한다.

# 27. 후속 개발 권장사항

## 27.1 우선순위 높음

### A. 수식 전환 기록

별도 이벤트 구조를 권장한다.

```javascript
{
  type: "formula-change",
  t: 12.4,
  from: "v1",
  to: "v2"
}
```

그래프에 전환 마커를 추가하면 해석이 쉬워진다.

### B. 재현 가능한 환경

다음을 분리하는 것이 좋다.

- 환경용 시드 난수
- 시각화용 난수

추가하면 유용한 기능:

- 시드 입력
- 동일 환경으로 재실행
- 환경 변화 켜기·끄기

### C. 모델·렌더링 분리

단일 파일 형식은 유지하더라도 내부 구조를 나누면 테스트가 쉬워진다.

예:

```text
Model
  수식
  환경
  적분

SimulationState
  현재 상태
  시간
  기록

Renderer
  생태계
  그래프
  피라미드

UIController
  입력
  버튼
  설정
```

## 27.2 우선순위 중간

- 변경 기록 CSV 내보내기
- 현재 설정 JSON 저장·불러오기
- 모바일 그래프 라벨 개선
- 일시정지 중 렌더링 최적화
- 기록 표 가상 스크롤
- 수식별 나란히 비교 화면

## 27.3 요구사항에 따라 검토

사용자가 “반영 속도”를 더 생태적으로 표현하기 원하면 다음 모델을 고려할 수 있다.

### 지연 먹이 반응

소비자가 현재 먹이량이 아니라 일정 시간 전 먹이량에 반응한다.

### 적응 상태

현재 변화율이 목표 변화율을 서서히 따라가도록 별도 상태를 둔다.

예:

\[
\frac{dR}{dt}
=
\frac{F(N)-R}{\tau}
\]

\[
\frac{dN}{dt}=R
\]

다만 이는 현재 v2와 다른 모델이며, 다음 문제를 새로 검토해야 한다.

- 음수 방지
- 과도한 관성
- 진동 증가
- 수식 전환 시 적응 상태 초기화
- 수치 안정성

현재 요구사항을 임의로 이 방식으로 바꾸지는 않는 것이 좋다.

# 28. 유지해야 할 핵심 원칙

다른 프로그래머가 수정할 때 다음 사항을 우선 보존해야 한다.

1. **수식v1은 기존 방정식 그대로 유지한다.**
2. **수식v2는 선택 가능한 별도 모델로 유지한다.**
3. **수식을 바꿔도 현재 개체수와 시간이 갑자기 바뀌지 않아야 한다.**
4. **직접 추가·감소는 즉시 적용한다.**
5. **직접 조절과 자연적인 변화는 기록과 설명에서 구분한다.**
6. **그래프는 실수 계산값, 도형과 주요 숫자는 반올림값을 사용한다.**
7. **정확히 0인 개체군은 직접 추가하기 전까지 재생성하지 않는다.**
8. **시각적 이동은 개체수 수식에 영향을 주지 않는다.**
9. **피라미드는 개체수 피라미드로 설명한다.**
10. **수식v2를 단순 배속 변경이나 시간 지연 모델로 설명하지 않는다.**
11. **수식 설정은 i 버튼 안내 화면의 맨 아래에 둔다.**
12. **기본 배포 형식은 외부 의존성이 없는 단일 HTML 파일이다.**

# 29. 인수인계용 최종 요약

이 프로그램은 생산자·1차 소비자·2차 소비자의 연속 개체수 변화를 계산하는 단일 HTML 교육용 시뮬레이션이다.

기존 모델인 **수식v1**은 로지스틱 성장, 섭식·포식, 사망, 밀도 의존 감소를 사용한다. 환경은 상관된 확률 과정으로 변하며 성장률·수용력·사망률에 영향을 준다.

추가된 **수식v2**는 수식v1의 변화율을 다음 식으로 완화한다.

\[
F_2
=
\frac{F_1}
{2+\frac{|F_1|}{0.12\max(N,1)}}
\]

이 방식은 같은 상태에서 증가·감소 방향과 평형 조건을 유지하면서, 작은 변화는 약 절반 속도로, 큰 변화는 더 강하게 완화한다.

수식 선택은 다음 위치에서 가능하다.

> **하단 i 버튼 → 시뮬레이션 수식 설정**

수식 전환은 시간·개체수·기록을 초기화하지 않으며 다음 계산부터 반영된다. 직접 개체수 조절은 두 수식 모두 즉시 적용한다.

시각화는 다음 세 가지다.

- Canvas 기반 개체별 생태계
- Canvas 기반 개체수 그래프
- SVG 기반 개체수 피라미드

계산은 고정 간격 RK4를 사용하고, 모든 데이터는 메모리에만 존재한다. 향후 개발에서는 **수식 전환 이력, 시드 기반 환경 재현, 수치 안정성, 대량 개체 성능**을 우선 개선하는 것이 권장된다.
